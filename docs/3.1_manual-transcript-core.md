# Sermon Analyzer — Manual Transcript Core

## Purpose

The Manual Transcript Core is the first buildable workflow.

Its job is simple:

**take one sermon video/source manually, produce one canonical transcript artifact, save minimal state**

Nothing else is required for this workflow to be successful.


---

## Success Criteria

The workflow is successful if it can:


 1. accept a manually provided sermon input
 2. resolve a deterministic `sermonId`
 3. check whether a valid transcript already exists
 4. reuse transcript if valid and not forced
 5. otherwise fetch media
 6. extract/normalize audio
 7. transcribe
 8. normalize transcript into canonical JSON
 9. save transcript artifact
10. update minimal registry/state
11. return success/failure clearly


---

## Scope

### In scope

* manual trigger

* one source URL or direct media URL

* forced retranscribe option

## Core Processing Logic


 1. Normalize request
 2. Resolve sermon identity
 3. Check registry/state
 4. Check transcript artifact
 5. Reuse decision
 6. Acquire media
 7. Prepare audio
 8. Transcribe
 9. Normalize transcript
10. Save transcript artifact
11. Update registry
12. Return result

## Exact n8n Node Map

### Big picture flow

```text
Manual Trigger
  -> Set Test Sermon Input
  -> Normalize Input
  -> Resolve Sermon Identity
  -> Build Paths
  -> Load Registry Record
  -> Check Existing Transcript Artifact
  -> Decide Transcript Action
      -> [REUSE]
      -> [TRANSCRIBE]

[REUSE]
  -> Load Existing Transcript
  -> Validate Loaded Transcript
  -> Build Success Result
  -> Update Registry Success
  -> Return Success

[TRANSCRIBE]
  -> Resolve Media Source
  -> Download Media
  -> Prepare Audio
  -> Transcribe Audio
  -> Normalize Transcript
  -> Save Transcript JSON
  -> Save Transcript TXT (optional)
  -> Build Success Result
  -> Update Registry Success
  -> Return Success

[Any Failure]
  -> Build Error Record
  -> Update Registry Failure
  -> Return Failure
```

## Recommended First Implementation Shortcuts

* require direct `mediaUrl`
* skip `sourceUrl` resolution logic initially
* support one transcription provider only
* store files locally
* keep review flags minimal
* use one file per sermon registry


---

## Required Artifacts

* canonical transcript JSON
* optional transcript text file
* minimal registry record


---

## Definition of Done


1. deterministic `sermonId`
2. transcript created and saved
3. registry updated
4. rerun reuses transcript by default
5. forced rerun retranscribes when requested
6. failure path returns structured error
7. artifact path is stable and predictable
