# 1.0 Requirements

## 1.1 System Overview

The Sermon Analyzer system processes sermon video/audio content to produce structured outputs including transcripts, notes, outlines, and analytical artifacts. The system is designed to be deterministic, configurable, and reusable across sermon series.

## 1.2 Input Model

The system receives a JSON configuration payload containing:

* church metadata
* doctrine reference
* people registry
* source URLs
* series configuration
* processing mode
* output configuration

## 1.3 Content Classification

Content is classified into the following primary types:

### 1.3.1 SERVICE

Non-sermon service elements such as announcements, singing, and offering.

### 1.3.2 SCRIPTURE_READING

Scripture passages read prior to or within the sermon, possibly by another speaker.

### 1.3.3 SERMON

Primary preaching content delivered by Pastor Mark.

### 1.3.4 BENEDICTION

Closing portion of the service; included in transcript but not part of sermon body.

## 1.4 Feature Tagging

Feature tags apply only to sermon content.

### 1.4.1 HUMOR

### 1.4.2 SARCASM

### 1.4.3 ANALOGY

### 1.4.4 CURRENT_EVENT

### 1.4.5 BIBLICAL_EVENT

### 1.4.6 POLITICAL_EVENT

### 1.4.7 NATURAL_DISASTER

## 1.5 Sermon Boundary Rules

* Opening prayer indicates likely sermon start
* Scripture Reading is included but separate
* Benediction marks end of sermon body
* Transcript continues to end of recording

## 1.6 Series Model

A sermon may belong to a series defined by:

* name
* type: BOOK, PERSON, TOPICAL, NONE
* start date
* optional end date

## 1.7 Processing Modes

* SINGLE_SERMON
* HISTORICAL_BATCH
* ONGOING_SCHEDULED

## 1.8 Doctrine Alignment

Sermon content is compared against doctrinal statements.

Statuses:

* aligned
* implicit
* ambiguous
* conflict
* contradiction

## 1.9 Viewpoint Handling

Viewpoints are classified as:

* endorsed
* rejected
* uncertain

Only endorsed or rejected viewpoints are reinforced.

## 1.10 Output System

Outputs include:

* transcript
* church notes
* analytical outline
* doctrine report
* improvement log

## 1.11 Voice Configuration

Each output defines its own voice:

* LISTENER_THIRD_PERSON
* EDITORIAL_THIRD_PERSON
* PASTOR_FIRST_PERSON
* DIRECT_TO_READER
* FORMAL_NEUTRAL

## 1.12 Event Classification

The system must distinguish between current events and biblical events based on context.

## 1.13 Entity Tagging

People are tagged into categories:

* FAMILY
* STAFF
* PASTOR
* READER
* AUTHOR
* COMMENTATOR
* BIBLICAL_PERSON
* OTHER_PERSON

## 1.14 Copyright Constraints

Full service recordings may contain copyrighted material. The system should prioritize sermon-safe content.

## 1.15 Logging & Feedback

The system generates improvement logs and flags uncertainties for review.
