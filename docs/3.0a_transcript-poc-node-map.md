# Sermon Analyzer — Transcript POC Node Map

## Purpose

This document defines the exact first workflow for proving the transcription pipeline.

This is **not** the full Sermon Analyzer workflow.

This is only the first proof of concept:

**URL -> media/audio -> transcription -> transcript file**


---

## Workflow Name

`SA - Transcript POC`


---

## Goal

Manually run one workflow that:


1. uses one hardcoded test sermon URL
2. fetches media or audio
3. prepares audio if needed
4. sends it to the transcription provider
5. receives transcript text
6. writes transcript output to a file
7. returns success or failure


---

## Big Picture Flow

```text
Manual Trigger
  -> Set Test Input
  -> Validate Input
  -> Resolve Output Paths
  -> Download Media
  -> Prepare Audio
  -> Transcribe Audio
  -> Extract Transcript Text
  -> Save Transcript File
  -> Return Success

[Any Failure]
  -> Build Error Result
  -> Return Failure
```


---

## Workflow Assumptions

For the POC, assume:

* one manually entered hardcoded URL
* one known transcription provider
* one local output directory
* no registry
* no transcript reuse
* no canonical schema requirement yet
* no discovery logic
* no metadata persistence beyond what is needed to name the file


---

## Required Inputs

Minimum required test input:

* `title`
* `date`
* `mediaUrl`

Optional:

* `speaker`
* `sourceType`
* `notes`

### Example Input

```json
{
  "title": "Blessed Are the Merciful",
  "date": "2026-03-22",
  "mediaUrl": "https://cdn.example.org/audio/2026-03-22.mp3",
  "speaker": "Pastor Mark",
  "sourceType": "WEBSITE"
}
```


---

## Output

Minimum required output:

* one transcript text file written locally

Optional output:

* raw provider response file
* temp audio file for debugging


---

## Node List

### 1. Manual Trigger

**Type**

* Manual Trigger

**Purpose**

* manually start the workflow

**Input**

* none

**Output**

* workflow start signal


---

### 2. Set Test Input

**Type**

* Set

**Purpose**

* define one hardcoded sermon test object

**Fields**

* `title`
* `date`
* `mediaUrl`
* optional `speaker`
* optional `sourceType`

**Example**

```json
{
  "title": "Blessed Are the Merciful",
  "date": "2026-03-22",
  "mediaUrl": "https://cdn.example.org/audio/2026-03-22.mp3",
  "speaker": "Pastor Mark",
  "sourceType": "WEBSITE"
}
```


---

### 3. Validate Input

**Type**

* Code

**Purpose**

* make sure the POC has enough to run

**Checks**

* `title` exists
* `date` exists
* `mediaUrl` exists

**Failure**

* missing required input should go to failure path


---

### 4. Resolve Output Paths

**Type**

* Code

**Purpose**

* build predictable local file paths for output

**Suggested output values**

* `titleSlug`
* `outputDir`
* `downloadPath`
* `audioPath`
* `transcriptTxtPath`
* optional `rawResponsePath`

### Example

```json
{
  "titleSlug": "blessed-are-the-merciful",
  "outputDir": "./output/2026-03-22-blessed-are-the-merciful",
  "downloadPath": "./output/2026-03-22-blessed-are-the-merciful/source-media",
  "audioPath": "./output/2026-03-22-blessed-are-the-merciful/audio.wav",
  "transcriptTxtPath": "./output/2026-03-22-blessed-are-the-merciful/transcript.txt",
  "rawResponsePath": "./output/2026-03-22-blessed-are-the-merciful/raw-response.json"
}
```


---

### 5. Download Media

**Type**

* HTTP Request
* or equivalent file download node

**Purpose**

* download the media from `mediaUrl`

**Input**

* `mediaUrl`

**Output**

* local downloaded file path

**Failure examples**

* bad URL
* timeout
* media unavailable


---

### 6. Prepare Audio

**Type**

* Execute Command

**Purpose**

* use ffmpeg if needed to convert the source media into a transcription-ready audio file

**Input**

* downloaded media path

**Output**

* normalized audio file path

**POC simplification**
If the input media is already in a provider-acceptable audio format, this step can be simplified or bypassed.

**Recommended default**

* normalize to one standard audio format anyway for consistency


---

### 7. Transcribe Audio

**Type**

* HTTP Request

**Purpose**

* send audio to one configured transcription provider

**Input**

* prepared audio file
* provider credentials

**Output**

* raw transcription response

**Requirements**

* one provider only for POC
* no provider abstraction layer yet


---

### 8. Extract Transcript Text

**Type**

* Code

**Purpose**

* extract plain transcript text from provider response

**Input**

* raw provider response

**Output**

* plain transcript text string

**Optional**

* also pass through raw response for optional debugging save


---

### 9. Save Transcript File

**Type**

* Write File

**Purpose**

* write transcript text to local disk

**Output**

* local transcript file path

**Required**

* transcript text file

**Optional**

* save raw provider response file too


---

### 10. Return Success

**Type**

* Set or Code

**Purpose**

* return a compact success result

### Example

```json
{
  "status": "SUCCESS",
  "title": "Blessed Are the Merciful",
  "date": "2026-03-22",
  "mediaUrl": "https://cdn.example.org/audio/2026-03-22.mp3",
  "transcriptTxtPath": "./output/2026-03-22-blessed-are-the-merciful/transcript.txt"
}
```


---

## Failure Path

### 11. Build Error Result

**Type**

* Code

**Purpose**

* standardize failure response

### Example

```json
{
  "status": "FAILED",
  "failedStage": "TRANSCRIBE_AUDIO",
  "errorMessage": "Provider timeout"
}
```


---

### 12. Return Failure

**Type**

* Set or Code

**Purpose**

* return structured failure result


---

## Branching Model

### Main Path


 1. Manual Trigger
 2. Set Test Input
 3. Validate Input
 4. Resolve Output Paths
 5. Download Media
 6. Prepare Audio
 7. Transcribe Audio
 8. Extract Transcript Text
 9. Save Transcript File
10. Return Success

### Failure Path

* any failed node routes to:

  
  1. Build Error Result
  2. Return Failure


---

## Minimal File Outputs

### Required

* `transcript.txt`

### Optional

* `raw-response.json`
* normalized audio file retained for debugging


---

## First Implementation Shortcuts

To keep the POC small:

* require direct `mediaUrl`
* no source-page scraping
* no registry
* no canonical transcript JSON yet
* no transcript reuse yet
* no metadata file yet
* no multi-provider support
* local files only


---

## Definition of Done

This node map is proven when:


1. workflow can be manually started
2. hardcoded media URL works
3. transcript is successfully produced
4. transcript text file is written locally
5. same workflow can be rerun with different backlog test URLs


---

## What Comes Next After POC Works

Once this workflow succeeds reliably, the next steps are:


1. harden transcript output
2. define canonical transcript artifact
3. add minimal registry/state
4. process backlog sermons during testing
5. move downstream into analysis
6. later move upstream into better acquisition and discovery
