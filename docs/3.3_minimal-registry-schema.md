# Sermon Analyzer — Minimal Registry Schema

## Purpose

The minimal registry schema is the MVP sermon state record.

It exists to track:

* sermon identity
* processing status
* transcript status
* transcript artifact reference
* rerun/reuse eligibility
* error and review flags

It is intentionally small.

The registry is not the transcript.
The registry is not the analysis artifact.
The registry is the state record that points to them.


---

## MVP Design Goals

The registry should:


1. support transcript reuse
2. support success/failure tracking
3. support rerun decisions
4. support simple per-sermon state storage
5. stay small and easy to inspect manually


---

## Storage Approach

Recommended MVP approach:

* **one JSON file per sermon**

Why:

* simpler than a master registry file
* avoids merge contention
* easier manual inspection
* easier per-sermon recovery

Suggested path:

```text
registry/{churchId}/{date}-{titleSlug}.json
```

Example:

```text
registry/fbc-example/2026-03-22-blessed-are-the-merciful.json
```

## Required Fields

### Identity / metadata

* `schemaVersion`
* `artifactType`
* `sermonId`
* `churchId`
* `title`
* `titleSlug`
* `date`
* `sourceType`

### Optional but strongly recommended metadata

* `sourceUrl`
* `mediaUrl`
* `externalId`
* `speaker`
* `seriesName`
* `seriesType`

### Processing state

* `status`
* `firstProcessedAt`
* `lastProcessedAt`
* `lastAction`

### Transcript state

* `transcriptStatus`
* `transcriptVersion`
* `transcriptCreatedAt`
* `transcriptProvider`
* `transcriptArtifactRef`
* `transcriptInvalidated`
* `transcriptInvalidationReason`

### Flags

* `errorFlags`
* `reviewFlags`


---

## Field Definitions

### `schemaVersion`

Type: string

Registry schema version.

### `artifactType`

Type: string

Fixed value:

```json
"SERMON_REGISTRY_RECORD"
```

### `sermonId`

Type: string

Deterministic sermon identity.

### `status`

Type: string

Allowed MVP values:

* `SUCCESS`
* `FAILED`
* `IN_PROGRESS`

Optional later values:

* `SKIPPED_ALREADY_PROCESSED`
* `SKIPPED_NOT_IN_SERIES`

### `firstProcessedAt`

Type: ISO datetime string

Set the first time the sermon is ever processed.

### `lastProcessedAt`

Type: ISO datetime string

Updated on every run attempt.

### `lastAction`

Type: string

Allowed MVP values:

* `CREATED_NEW_TRANSCRIPT`
* `REUSED_EXISTING_TRANSCRIPT`
* `FAILED_PROCESSING`

### `transcriptStatus`

Type: string

Allowed MVP values:

* `READY`
* `MISSING`
* `INVALID`
* `FAILED`

### `transcriptVersion`

Type: integer

Starts at `1`. Increment only if transcript is deliberately regenerated.

### `transcriptCreatedAt`

Type: ISO datetime string

When the current transcript artifact was created.

### `transcriptProvider`

Type: object

Required fields:

* `name`
* `model`

### `transcriptArtifactRef`

Type: string

Path to the canonical transcript JSON artifact.

### `transcriptTextArtifactRef`

Type: string

Optional path to plain text transcript artifact.

### `transcriptInvalidated`

Type: boolean

Whether the current transcript has been deliberately invalidated.

### `transcriptInvalidationReason`

Type: string or null

Why the transcript was invalidated.

### `errorFlags`

Type: array of strings

Errors that affected processing.

Examples:

* `MEDIA_DOWNLOAD_FAILED`
* `AUDIO_PREPARATION_FAILED`
* `TRANSCRIPTION_FAILED`
* `TRANSCRIPT_SAVE_FAILED`
* `REGISTRY_WRITE_FAILED`

### `reviewFlags`

Type: array of strings

Non-fatal warnings needing manual review.

Examples:

* `LARGE_UNINTELLIGIBLE_SECTION`
* `SHORT_TRANSCRIPT`
* `LOW_AUDIO_QUALITY`
* `LANGUAGE_UNCERTAIN`


---

## Validation Rules

A valid MVP registry record must have:

* `schemaVersion`
* `artifactType == SERMON_REGISTRY_RECORD`
* `sermonId`
* `churchId`
* `title`
* `titleSlug`
* `date`
* `sourceType`
* `status`
* `lastProcessedAt`
* `transcriptStatus`
* `transcriptVersion`
* `errorFlags` array
* `reviewFlags` array

If `transcriptStatus == READY`, then also require:

* `transcriptCreatedAt`
* `transcriptProvider.name`
* `transcriptProvider.model`
* `transcriptArtifactRef`


---

## Reuse Decision Support

The registry supports transcript reuse when:

* `transcriptStatus == READY`
* `transcriptInvalidated == false`
* `transcriptArtifactRef` exists
* artifact file exists and validates
* no explicit `forceRetranscribe` flag is set

The registry should not be the only source of truth for reuse.
The workflow must still validate the transcript artifact itself.


---

## What the Registry Should Not Store

Do not store these in the registry:

* transcript `fullText`
* transcript `segments`
* raw provider response
* analysis output
* doctrine output
* generated notes/output content

The registry should point to artifacts, not duplicate them.
