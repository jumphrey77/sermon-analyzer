# 8.1 Output Artifacts

## Purpose

Define generated outputs, naming, versioning, and storage conventions.

## Core Output Types

* transcript
* churchNotes
* analyticalOutline
* doctrineReport
* improvementLog
* followUpStudy
* paragraphSummary
* bookSummary

## MVP Default Outputs

* transcript
* churchNotes
* analyticalOutline
* doctrineReport
* improvementLog

## Per-Output Configuration

Each output supports:

* enabled
* voice (first_person, third_person, editorial)
* includeQuotes (true/false)
* expansionLevel (low, medium, high)
* citationStyle (inline, footnote)

## Directory Structure

output/
YYYY-MM-DD/
transcript/
church-notes/
analytical-outline/
doctrine-report/
improvement-log/
follow-up-study/
paragraph-summary/
book-summary/

## File Naming Convention

DATE_SERIES_TITLE_OUTPUTTYPE_VERSION

### Example

2026-03-08_Matthew_Genealogy_transcript_v1.md

### Naming Rules

* replace spaces with hyphens
* remove special characters
* keep consistent casing
* avoid duplicate separators

## Versioning

* each workflow run generates a new version
* do not overwrite previous outputs
* version format: v1, v2, v3

### Examples

* transcript_v1.md
* transcript_v2.md
* analytical-outline_v1.md

## Artifact Metadata (required)

Each output must be traceable with:

* sermonId
* sermonDate
* sourceUrl
* workflowVersion
* promptBundleVersion
* outputVersion
* generatedTimestamp

## Registry References

Each artifact should be recorded in the registry with:

* outputType
* version
* filePath
* generatedAt

## Output Expectations

### Transcript

* near-verbatim transcription
* include unintelligible markers where audio is unclear
* include structure markers if detected

### Church Notes

* concise, listener-style notes
* key verses
* main points
* supporting observations

### Analytical Outline

* structured hierarchy
* introduction, main points, subpoints
* analogies, humor, and references tagged

### Doctrine Report

* doctrine alignment summary
* flag conflicts with church doctrine
* include supporting passages

### Improvement Log

* AI observations
* uncertainty areas
* suggested improvements to workflow

## Optional Outputs

### Follow-Up Study

* questions for further study
* discussion prompts
* scoped to sermon passage

### Paragraph Summary

* concise readable paragraph
* high-level overview

### Book Summary

* expanded narrative form
* configurable voice (first or third person)
* includes structured citations

## Storage Rules

* only generate outputs that are enabled in config
* preserve all historical versions
* ensure deterministic file paths
* do not mix outputs from different sermons in the same directory

## Future Enhancements

* artifact manifest per sermon
* JSON metadata companion file per output
* HTML/PDF rendering layer
* diff comparison between versions
