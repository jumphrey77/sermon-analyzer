# Sermon Analyzer — Doctrine Analysis Spec

## Purpose

Doctrine analysis compares a sermon against the active church's doctrinal baseline.

It is **church-profile-aware** and **church-doctrine-aware**.

It must not treat doctrine as:

* a generic theology blob
* a news article
* unstructured free text

Instead, doctrine analysis must operate against the active church's structured doctrinal source material.


---

## Core Principle

Doctrine analysis is scoped by `churchId`.

For each sermon run, the workflow must resolve:

* the active church profile
* the church's doctrinal source document
* the church's doctrine analysis hints

This means doctrine analysis is:

* shared workflow logic
* church-specific doctrinal comparison
* article-based, not blob-based


---

## Inputs

Doctrine analysis depends on these inputs:

### Required

* `churchId`
* sermon transcript or canonical transcript
* sermon metadata
* active church profile
* doctrinal source document for that church

### Optional

* sermon structure analysis
* extracted sermon scripture references
* extracted entities
* review flags from prior stages

## Doctrine Analysis Objectives

Doctrine analysis should answer four core questions:


1. **Which doctrinal articles does this sermon touch?**
2. **How does the sermon relate to those doctrinal articles?**
3. **What scripture references support that comparison?**
4. **Does anything require manual review?**


---

## Doctrine Analysis Types

### 1. Doctrine Article Matching

Determine which doctrinal article or articles are relevant to the sermon.

Examples:

* Scriptures
* The Triune God
* Justification
* Sanctification
* Security of the Saints
* Future Events
* Marriage & Family
* Human Sexuality

This match may be:

* direct
* partial
* secondary
* absent


---

### 2. Doctrine Alignment Analysis

Compare the sermon's teaching against the article text.

Allowed outcomes:

* `ALIGNED`
* `IMPLICIT`
* `AMBIGUOUS`
* `CONFLICT`
* `CONTRADICTION`

#### Definitions

##### `ALIGNED`

The sermon explicitly teaches materially the same doctrine as the article.

##### `IMPLICIT`

The sermon supports the article's doctrine but does not state it as directly or fully.

##### `AMBIGUOUS`

The sermon touches the doctrine area, but the stance is not clear enough to classify confidently.

##### `CONFLICT`

The sermon appears to push against part of the doctrinal statement, but the tension is not strong enough to mark as contradiction without review.

##### `CONTRADICTION`

The sermon clearly teaches contrary to the church's doctrinal article.


---

### 3. Doctrine Reference Analysis

Compare sermon scripture usage against the scripture references attached to doctrinal articles.

This is not just “did the sermon mention a Bible verse.”

It should evaluate things like:

* sermon uses the same references as the doctrinal article
* sermon uses related references supporting the same doctrine
* sermon teaches a doctrine article without citing the church's listed references
* sermon uses references in a way that appears to push against the church's doctrinal position

This is especially important when:

* the sermon series is from a book heavily cited in the Articles of Faith
* the sermon and doctrine statement overlap on the same passages
* the doctrine issue is high sensitivity


---

## Doctrine Source Structure

Doctrine analysis assumes the doctrinal source contains structured articles such as:

* `title`
* `description`
* `scripture_references`

Some articles may also contain sub-grouped references, such as:

* Baptism
* The Lord's Supper

Doctrine analysis must therefore support:

* simple reference lists
* grouped/subsection reference lists


---

## Recommended Workflow Position

Doctrine analysis should happen **after** transcript exists.

Preferred order:


1. transcript acquisition
2. transcript normalization
3. scripture/reference extraction
4. doctrine article matching
5. doctrine alignment analysis
6. doctrine reference analysis
7. review flag generation
8. doctrine report generation

It does not need to be part of the earliest transcript POC.


---

## Inputs to Compare

Doctrine analysis compares:

### Sermon-side inputs

* sermon transcript text
* sermon structure
* sermon scripture references
* sermon claims / viewpoints
* sermon entities if relevant

### Church-side inputs

* doctrinal article text
* doctrinal article scripture references
* doctrine sensitivity hints
* church profile context


---

## Viewpoint Handling

Doctrine analysis must respect viewpoint rules.

For sermon claims related to doctrine, the system should classify claims as:

* `ENDORSED`
* `REJECTED`
* `UNCERTAIN`

Rule:

* reinforce `ENDORSED`
* reinforce `REJECTED`
* do not overstate `UNCERTAIN`

This matters because a sermon may mention a contrary view only to reject it.

The analyzer must avoid falsely classifying rejected views as the sermon’s own doctrine.


---

## Sensitivity Handling

Some doctrine areas should trigger stronger review when unclear.

Examples of likely high-sensitivity areas:

* security of the saints
* future events
* marriage and family
* human sexuality
* personal separation

Sensitivity should not change truth classification.
It should affect:

* review thresholds
* confidence handling
* flag severity


---

## Recommended Output Shape

Doctrine analysis should produce structured output, not only prose.

Recommended output shape:

```json
{
  "churchId": "string",
  "sermonId": "string",
  "matchedArticles": [
    {
      "articleId": "string",
      "title": "string",
      "matchStrength": "DIRECT",
      "alignment": "ALIGNED",
      "sensitivity": "HIGH",
      "summary": "string",
      "supportingSermonReferences": [],
      "supportingDoctrineReferences": [],
      "notes": [],
      "reviewFlags": []
    }
  ],
  "overallDoctrineAssessment": {
    "status": "ALIGNED",
    "summary": "string"
  },
  "reviewFlags": []
}
```


---

## Field Notes

### `matchedArticles`

List of doctrinal articles the sermon meaningfully touches.

### `matchStrength`

Recommended MVP values:

* `DIRECT`
* `PARTIAL`
* `SECONDARY`

### `alignment`

Allowed values:

* `ALIGNED`
* `IMPLICIT`
* `AMBIGUOUS`
* `CONFLICT`
* `CONTRADICTION`

### `supportingSermonReferences`

References actually used or clearly implied in the sermon.

### `supportingDoctrineReferences`

References listed in the church’s doctrinal article.

### `reviewFlags`

Flags for article-level concerns.

### `overallDoctrineAssessment`

A compact summary across all matched articles.


---

## Recommended Review Flags

Examples:

* `DOCTRINE_MATCH_LOW_CONFIDENCE`
* `DOCTRINE_ALIGNMENT_AMBIGUOUS`
* `POTENTIAL_DOCTRINAL_CONFLICT`
* `POTENTIAL_DOCTRINAL_CONTRADICTION`
* `HIGH_SENSITIVITY_TOPIC`
* `SCRIPTURE_REFERENCE_MISMATCH`
* `VIEWPOINT_CLASSIFICATION_UNCERTAIN`

These are not final required names, but the pattern should be structured and explicit.


---

## Matching Rules

### Article matching should consider:

* doctrine keywords
* theological concepts
* article description language
* sermon claims
* sermon scripture references
* book/chapter context when helpful

### Matching should not rely only on keyword overlap

A sermon may clearly address sanctification without repeating the exact article title.

### Matching should support multiple articles

One sermon may legitimately touch:

* justification
* sanctification
* security of the saints


---

## Alignment Rules

### Aligned

Use when sermon teaching materially affirms the article.

### Implicit

Use when sermon supports the article but with lower specificity.

### Ambiguous

Use when the evidence is mixed, underdeveloped, or too weak to classify.

### Conflict

Use when the sermon creates tension with the doctrinal article.

### Contradiction

Use when the sermon clearly teaches against the doctrinal article.

### Important rule

Do not escalate to `CONTRADICTION` unless the sermon’s own teaching is clear.

Mentioning an alternative view is not enough.
The sermon must endorse the contrary teaching for contradiction to be valid.


---

## Scripture Reference Analysis Rules

Doctrine reference analysis should compare:

* sermon references
* doctrinal article references

Possible findings:

* exact overlap
* related support
* no overlap but aligned teaching
* potentially contrary usage
* unclear reference relationship

This helps explain *why* an article was classified as aligned or conflicting.


---

## What Doctrine Analysis Should Not Do

Do not:

* treat church doctrine as one flat text blob
* assume one church profile globally
* ignore `churchId`
* classify every sermon as touching every article
* confuse mentioned views with endorsed views
* force contradiction when ambiguity is more honest
* replace human review on sensitive conflicts


---

## Recommended Dependencies

Doctrine analysis should ideally consume:

* canonical transcript
* extracted sermon scripture references
* church profile
* church doctrinal source

It may optionally consume:

* sermon structure analysis
* viewpoint extraction


---

## Definition of Done

Doctrine analysis is working when it can:


1. load doctrine for the active `churchId`
2. identify which doctrinal articles a sermon touches
3. classify alignment per matched article
4. compare sermon references against doctrinal references
5. flag ambiguity or conflict clearly
6. produce structured output suitable for later doctrine reports


---

## Summary

Doctrine analysis is not generic content classification.

It is a church-scoped comparison between sermon teaching and structured doctrinal articles.

It must support:

* article matching
* doctrinal alignment
* doctrine reference analysis
* sensitivity-aware review
* viewpoint-aware interpretation

All of this must be resolved from the active church profile and doctrinal source for the current `churchId`.
